00 / Research question

Can a compact policy stay reliable when perception, planning, and control run at different speeds?

Hello Gripper is our working answer: a reproducible place-cube task, a high-throughput demonstration engine, a multimodal action-chunking policy, and a three-clock runtime that keeps physics responsive while the network thinks.

01 / The system

One continuous research loop.

Every subsystem shares explicit timing, action, task, and episode contracts. A demonstration collected today can be replayed, inspected, trained on, and benchmarked without a separate conversion pipeline.

Reference task · place_cube_random_box_v1

Pick a randomly placed cube. Place it in a randomly placed box. Lift clear.

The task is intentionally small but complete: randomized geometry and visuals, contact-rich grasping, explicit success and failure rules, and enough variation to expose brittle policies.

  • Success cube in box + gripper clear
  • Failure timeout or unreachable cube
  • Variation spawn, box, cube, camera, light

02 / Async inference

Fast control.
Slow thinking.
No blocking.

The simulator never waits for a forward pass. Three independent clocks preserve the observation spacing used in training, decide when a fresh plan is needed, and replay the latest plan at control rate.

i

Single-slot queues evict stale work. New trajectories are time-stamped, so a late result can replace the old plan without jumping coordinate frames.

03 / Data engine

Data with a memory.

Episodes carry the context required to reproduce and diagnose them—not only pixels and actions, but task rules, randomization, control source, timing, and physical state.

Successful inference and hybrid model/teleop rollouts retain per-timestamp provenance.

One episode · synchronized at 100 Hz

A shared contract from collection to visualization.

Successes and optional failures are grouped by task, collection source, and result. Background workers write complete HDF5 artifacts atomically and generate compact review videos.

episode_*.h5 ├── time ├── frames/overview ├── actions/{command, residual} ├── poses/{mocap, palm, cube, fingers} ├── control/control_source └── metadata/{task, result, seed, overrides}

04 / Policy

See. Remember. Predict a horizon.

07 / Reproduce it

Start with one command.

The repository includes environment setup, task automation, training, visualization, deterministic benchmarks, and current-state architecture notes.

Documentation ↗ Architecture notes ↗ Data collection ↗ Benchmarking ↗
quick-start.sh
# Install simulation + model dependencies
$ bash scripts/setup_dev.sh --model

# Collect randomized expert demonstrations
$ .venv/bin/python scripts/expert_recorder.py \
    --num-episodes 100 --random-visuals \
    --random-camera --random-cube-size

# Train with cached frozen visual features
$ .venv/bin/python train.py \
    --task place_cube_random_box_v1 \
    --image-encoder dino --feature-cache

# Deploy a checkpoint in the live simulator
$ .venv/bin/python interactive_gripper.py \
    --control model --checkpoint checkpoints/run/last.pt
